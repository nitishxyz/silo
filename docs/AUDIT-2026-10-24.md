# Code audit: 2026-10-24

A read-only audit of the code at `49c80ac` (v0.1.10 plus two test fixes). Three agents each covered one area and cited
file:line for every claim. Where their claims were surprising, they were checked by hand, and those checks are marked
**verified**. The audits did not run anything, so "tested" means a test file exists. Separately, a full local run of
`cargo test --workspace` passed (1,350 tests), and CI was green on `main` and `otto` at `49c80ac`.

Where this audit and `PLAN.md`, `GAPS.md` or `OTTO.md` disagree, the code is the source of truth (see §5).

Labels: **DONE**, **PARTIAL**, **MISSING**, **FRAGILE**, **UNVERIFIED**.

## 1. Silo core

Covers silo-server, silo-proto, silo-client, silo-transport, silo-pty, silo-vt, silo-store, silo-cli, silo-tools and
CI.

### Sessions, windows, blocks, layout, floats, parked
- **DONE**: split, park, reveal, zoom, swap, float, move and ratio (`silo-server/src/registry.rs:891-1140`).
- **DONE**: step, focus by direction, grow, edge and equalize (`layout_cmds.rs:38-54`).
- **Tests**: `tests/parked.rs`, `tests/lifecycle.rs`.
- **DONE**: closing a busy block, window or session is refused unless forced (`conn.rs:423-430`,
  `close_guard.rs:63-72`). The `force: _` patterns at `conn.rs:535/547/581` are safe because the guard runs first.
  Clients opt in through `compat::OPT_IN`.

### Terminal engine
- **DONE**: attach resumes when the epoch matches and the offset is still in the ring or log. Otherwise it sends a
  libghostty snapshot and streams the history (`block.rs:2260-2300`). Slow subscribers are cut off (`block.rs:46`).
- **DONE**: encrypted client cache (`silo-client/src/cache.rs`).
- **Tests**: `silo-server/tests/stream.rs`, `silo-client/tests/{resume,cache}.rs`.
- **DONE**: libghostty is pinned by `GHOSTTY_REV` and built with zig for macOS arm64/x86_64 and Linux x86_64/aarch64
  (`build-ghostty.sh:21-25`). It is statically linked into `silo` (77 `ghostty_` symbols).
- **PARTIAL**: the differential fuzz test is `#[ignore]` (`silo-vt/tests/differential.rs:308`). CI runs only the
  short cases, natively and on an emulated Haswell.

### Persistence and crash restore
- **DONE**: a sealed manifest plus one checkpoint per block (`persist.rs:106-165`), encrypted with
  XChaCha20-Poly1305 (`silo-store/src/key.rs:48`).
- **PARTIAL** (**verified**): after a crash, a running block gets a fresh login shell in its last cwd, below the
  restored screen. The original command is not re-run (`persist.rs:171-179`).
- **PARTIAL**: parked blocks that have an owner are dropped on restart (`persist.rs:148`).
- **PARTIAL**: the key is a 0600 file next to the data (`key.rs:121`). There is no Keychain or Secret Service.

### Hot upgrade and takeover
- **DONE**: PTY masters are passed over SCM_RIGHTS with a READY/COMMIT handshake, and an old server that can't upgrade
  is detected (`handoff.rs:1-30, 208-221`). Linux and macOS differences are handled (`silo-pty/src/handoff.rs:79-103`,
  `host.rs:64-69`).
- **Tests**: `tests/upgrade.rs`, `handoff_block.rs`, `silo-pty/tests/handoff.rs`.
- Fixed after v0.1.10: a takeover now retries binding a fixed remote port for up to 3 s (`06eba56`).

### Remote
- **DONE**: iroh with relay Default, Custom or Disabled, plus mDNS (`silo-transport/src/net.rs:62-69`). The server
  enables mDNS by default (`lib.rs:105`).
- **DONE**: pairing create, list and revoke (`conn.rs:726-753`), and `silo join` (`silo-cli/src/main.rs:1142`).
- **DONE**: grants scoped to server, session or block, with view, interact or control rights (`conn.rs:447-500`).
- **DONE**: `silos1` share-link tickets (`silo-transport/src/share.rs`).
- **PARTIAL**: share links can only be created or opened in the app (`silo-app/src/share.rs:261`). `silo grant` mints
  tokens only (`main.rs:950-967`).
- **MISSING** (**verified**): `GrantKind::Account` returns "accounts need a login server" (`conn.rs:459`).
- **DONE**: tunnels reach server-private hosts and named services such as otto (`silo-server/src/tunnel.rs:126-165`).
  The app is the only client (`silo-app/src/web.rs:137`); there is no CLI verb.
- **Tests**: `tests/{remote,share,tunnel,access}.rs`, `silo-transport/tests/net.rs`.

### API surface
- **DONE**: 116 `Method` variants. A test checks the `METHODS` table against the variants, and every method has a
  schema, an example and an access rule (`api.rs:459-510`).
- **DONE**: the server's `match` has no wildcard arm (`conn.rs:510-828`), so the compiler forces a handler for every
  method.
- **By design**: `host.offer` is only valid during a join; normal dispatch answers forbidden (`conn.rs:292`, `754`).

### Browser forwarding and `browser.fetch`
- **DONE**: requests are forwarded to the app that owns the block, else to a browser-host app, preferring a local one
  over a trusted remote one (`app_bridge.rs:84-200`). Tests: `tests/browser.rs`, `silo-tools/tests/fetch.rs`.
- **PARTIAL**: CEF exists only on macOS (`silo-web/src/lib.rs:7`). A Linux server needs a paired Mac running the app,
  and its error text is hardcoded to "on this Mac" (`app_bridge.rs:27,30`).
- **New**: parked browsers through `block.spawn {kind: browser}` and the `parked_browsers` feature (`63f7520`).

### Status, notifications, attention, close guard, approvals
- **DONE**: status, notify and attention events are filtered by the client's STATUS feature (`registry.rs:240`).
- **DONE**: approvals, with process info on macOS (`approval.rs:468`) and Linux (`:479`).
- **Tests**: `status_block.rs`, `status_api.rs`, `approval.rs`, `close_guard.rs`.
- Note: `notify.rs` is systemd `sd_notify`, not desktop notifications.

### CLI
- **Verbs**: mcp, report, notify, hooks, server, up, join, remote install|upgrade, update (alias upgrade), down,
  status, pair, grant, grants, devices, id, hosts, ls, new, browser, attach, send, run, capture, float, kill,
  kill-server, events, clipboard, api list|describe|call, do, otto, paste, copy, shim, install.
- **DONE**: `silo do` builds its flags from `api.describe` (`generated.rs`).
- **Thin**: `report` exits 0 silently without `SILO_BLOCK` (`main.rs:601-603`). `--host` is refused for 13 verbs
  (`main.rs:578-592`).
- **Tests**: `silo-cli/tests/{verbs,do,run,kill,mcp,update,remote,remote_agent}.rs`.

### Install, update, release
- **DONE**: `install.sh` checks downloads against `SHA256SUMS`, installs to `~/.local/bin` and checks the glibc
  version (`site/install.sh:109-133`).
- **MISSING**: Intel Macs are refused (`install.sh:81-87`, `link.rs:118`). There is no musl build, and no deb or rpm
  packages.
- **PARTIAL**: Linux self-update checks only the SHA256 from the same release, with no signature. macOS also checks
  the code-signing identity (`silo-client/src/update.rs:1-30`).
- **DONE**: service management with systemd `Type=notify` plus linger, or launchd (`service.rs:57-332`). Without a
  systemd user session, Linux falls back to `Manager::None`.
- **PARTIAL (CI)**: Linux CI skips clippy and doesn't test `silo-tools` (`ci.yml:57-61`).

### Linux overall
- **DONE**: the server, PTY, handoff, clipboard (wl-copy or xclip, `sysclip.rs:90-145`), systemd and `/proc` process
  info.
- **MISSING**: the GUI and the browser engine (see §2).

## 6. Biggest real gaps

1. **Cross-machine agents (O8)**: nothing in code yet.
2. **The app is macOS-only**: it doesn't compile elsewhere. Linux `browser.*` and `app.*` calls need a paired Mac.
3. **Browser basics**: no downloads, context menu, file chooser, find-in-page, user DevTools or permission UI, and
   popups become splits.
4. **Crash restore** gives a fresh shell, not the original program.
5. **No account grants or login server.**
6. **App gaps**:
   - Relay and network can't be configured.
   - Keyboard shortcuts can't be remapped.
   - `Command::feature()` is dead.
   - No screen reader.
   - The menubar is thin.
7. **otto robustness**:
